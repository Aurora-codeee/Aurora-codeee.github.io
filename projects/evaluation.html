PROJECT 04

Agent 交付评测台

交付了 Word 和 PDF，还要确认 PDF 来自更新后的 Word。

01项目概览

为文档 Agent 接入 PDF 能力时，文件数量无法代表交付正确：Word 可能已修改，PDF 却仍来自旧稿。我独立设计验收条件、检查顺序和版本对照流程，借助 AI 实现界面与代码，由我验证。

关键设计：把“文件是否存在”与“文件从哪里来”分别检查。即使两份产物记录齐全，缺少更新稿的引用也不能放行。

已完成评测工作流与结构化判据校准 · 尚无真实模型版本对照结论

02从任务到验收

评测台将任务资料、验收条件、执行记录和采用结论放在同一工作流程中。首版 16 条任务覆盖新增能力、原有任务、组合交付及不应触发新能力的情况。

WORKBENCH / 产品全貌

从任务资料到人工准入，沿同一工作台推进。

03怎样判断交付正确

把“先修改 Word，再导出 PDF”拆成验收条件

合成任务要求：把 Word 从 v2.2 更新到 v2.3，补充回退方案，保留可编辑稿，再用更新稿导出可提取文字的 PDF。我按动作、顺序、引用与产物检查，定位第一处偏差。

每个条件都对应一种可能的交付错误
验收条件要排除的问题
Word 完成指定修改文件存在，但版本或回退方案没有更新。
先修改，再导出先导出 PDF，之后才修改 Word。
PDF 引用本次更新稿两份文件都有，却无法证明 PDF 来自更新稿。
格式满足使用要求Word 不可编辑，或 PDF 无法打开、提取文字。

程序核对文件、顺序与引用；开放表达可由模型提供第二意见，但不能推翻这些可直接核对的事实。

先验证评测器：正确的能通过，缺证据的会被拦截

我先用满足条件的结构化记录检查是否误拒，再逐项删除或改坏证据，检查是否漏判。下例只改变 PDF 对上游 Word 的引用。

已有校准结果：两份产物记录、指定修改与执行顺序都保留
唯一变化判定与原因
引用完整通过：导出输入指向本次更新稿。
引用缺失拦截：无法确认 PDF 来自本次修改后的 Word。

结构化校准修改的是执行记录字段，未让真实模型生成文件。另已检查顺序颠倒、空跑与原样透传的拦截。

新能力进入候选，不能以牺牲原有任务为代价

PDF 初版规则可能被“终稿、审阅”等宽泛表达触发。我为修订版明确格式与可编辑要求，并要求上游修改完成后再导出；评测设计保留接入前、初版与修订版三组对照。

采用时需在同一任务、数据、模型配置和判据下，逐题看新增通过、保持、退化与修复。新增能力通过、原有任务不退化且没有硬性错误，才进入人工候选评审。

04已形成的评测方案

已交付评测任务、验收条件、候选规则、评测工作台与结构化校准记录。校准将“交付是否正确”落实到具体证据，采用流程将新增能力和原有任务放在一起审阅。
