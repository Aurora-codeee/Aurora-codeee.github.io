01 项目概览

PROJECT 03 / 个人独立项目

个人项目 · 合成业务资料

文档 Agent 的 Skill 准入评测工作流

为文档 Agent 接入新 Skill 设计评测流程，同时检查新增能力、旧任务回归与跨 Skill 的文件交接，为采用决策提供依据。

个人独立项目｜独立设计与搭建｜AI 辅助实现2026.07 — 2026.08

为谁使用
为文档 Agent 接入、修订 Skill 的开发与评测人员
输入什么
任务资料、候选版本与验收要求
交付什么
证据判定、质量诊断与人工准入依据
我的贡献

独立设计初始评测集、交付合同、版本对照与判定流程；借助 AI 实现界面及代码，由我验证工作流与评测器。

要解决的问题

接入 PDF Skill 后，Agent 可能跳过 Word 修改、改变原本的交付格式，或使用错误的上游文件。验收需要检查完整任务链。

02方案流程

先定义交付，再用证据判断是否完成。

WORKBENCH / 产品全貌

从任务资料到人工准入，沿同一工作台推进。

阅读重点：左侧串起资料、任务、执行和准入；右侧将公开题面、源文件与证据合同入口放在同一行，便于按任务检查交付要求。

03设计与实例

用一个 Word → PDF 任务贯穿评测设计。

应用背景｜为已有文档 Agent 接入 PDF Skill

已有能力
Agent 已能处理表格、Word 和演示文稿，现在准备新增 PDF 交付能力。
接入风险
新 Skill 可能抢占原有任务、跳过上游修改，或读取错误文件。即使生成了 PDF，用户要求也可能没有完整完成。
决策目标
在相同任务与配置下，判断候选版本是否增加能力、保持旧任务表现，并正确完成跨 Skill 交接。

准入原则：有新增通过的任务、没有旧任务退化、没有硬性错误，才进入人工候选评审。

交付合同

把“完成任务”写成可检查的条件。

我构建了 16 条初始基准，覆盖新增能力、旧任务回归、跨 Skill 协作与负向边界。公开题面交给被测 Agent，隐藏验收合同由评测器读取。

C10 · 合成任务：先改文档，再交付两种格式

更新需求说明，补充“回退方案”；交付可编辑 Word，再从更新后的 Word 导出 PDF。

用户要求验收要检查的证据
补充回退方案更新后的 Word 包含指定修改，保持可编辑。
从更新稿导出 PDFWord 修改先于 PDF 导出，PDF 输入引用更新后的 Word。
交付两种格式Word 与 PDF 均存在，并检查文件能否打开、内容是否满足要求。

设计取舍：把任务要求拆成独立判据；仅有文件名或一句“已完成”，不足以支持放行。

版本对照

接入前、初版与修订版，回答不同的问题。

对照固定任务、数据、模型配置与判据，只改变接入的 Skill 规则。当前已完成工作流与判据校准，真实模型对照待补。

A0 / 接入前

原有文档能力

尚未接入 PDF Skill，作为任务能力基线。

A1 / 初版

触发范围过宽

遇到终稿、审阅或 PDF 就独占任务，可能抢占上游 Word 修改。

A2 / 修订版

明确格式与交接

先判断可编辑要求，完成上游修改后，再交给 PDF Skill。

以上为候选规则设计；效果需由同条件执行结果判断。

C10 要回答：交接是否修好？

检查上游修改是否完成、PDF 是否读取更新稿，并保留首次偏差与产物证据，判断修订是否有效。

旧任务还要回答：有没有退化？

对只要求可编辑 Word 的任务，检查是否仍按原格式交付，避免 PDF Skill 抢占原有能力。

比较依据：逐题区分新增通过、保持、退化和修复恢复；平均分上升不能抵消旧任务退化。

证据判定与人工准入

两个文件都有，还要检查它们如何衔接。

判据本身也可能误拒合格结果，或漏掉任务错误。我用合格正例检查误拒，再逐项破坏结构化证据检查漏判。下面两组记录只改变 PDF 的上游引用，判定就应不同。

更多校准例子：顺序错误与空跑

顺序错误 · 拦截

先导出 PDF，再修改 Word。即使最终都有产物记录，也不满足“从更新后的 Word 导出”的顺序要求。

precedence_violated

空跑 · 拦截

声称完成任务，却没有 Word／PDF 调用和产物记录，命中必需调用与产物缺失。

required_artifact_missing
判定顺序：Checkpoint（硬性检查）先拦截文件、顺序和交接错误；Rubric（质量量表）再诊断问题；最后由人审阅证据并决定是否进入候选。

没有评测结论时，填写确认人也不能放行。

当前尚无可确认结论，“标记 A2 为本地候选”保持不可用。具名确认必须建立在评测证据之上。

实际未运行状态 · 用于展示确认约束，未产生 A0／A1／A2 模型对照成绩。

04交付与验证

先把评测标准做实，再为版本采用提供依据。

  1. 01

    定义风险与交付标准

    围绕新增能力、旧任务、跨 Skill 交接和负向边界，设计初始评测集、公开题面、隐藏合同与候选版本规则。

  2. 02

    搭建评测与人工准入工作流

    借助 AI 实现界面与代码，将执行记录、产物、逐项判定和失败定位组织为人工评审依据，由我验证工作流。

  3. 03

    验证产物处理，并校准评测器

    历史自动化检查覆盖文件生成、交接与判定。针对 C10，另用结构化正负例校准判据，检查误拒与漏判。

C10 结构化判据校准

校准输入检查结果
满足合同的合格证据通过硬性检查。
空跑／原样透传分别被必需执行证据与质量判据拦截。
删除交接引用／颠倒顺序分别定位为交接缺失与顺序错误。

结果来自本地结构化校准；真实文件质量另需结合执行产物检查。

交付成果

16 条初始基准、验收合同、候选版本规则与评测工作台，形成从任务要求到证据判定、再到人工候选评审的完整设计。
