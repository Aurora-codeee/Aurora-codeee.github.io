01 项目概览

PROJECT 02 / 腾讯 CSIG

真实实习 · 产品方案与 Demo 验证

内容生产与反馈协作 Agent 方案

ContentLoop 将内容生产、人工决策与反馈交接组织成可接续的工作流，让下一轮工作有明确的产物与方向依据。

腾讯 CSIG｜产品经理实习生｜AI Agent 方向2026.06 — 2026.08

为谁使用
跨天协作、持续生产与复盘的内容团队
输入什么
素材、已确认方向与发布反馈
交付什么
内容产物、交接记录与偏好候选
我的贡献

参与整体方案、责任链及业务 Skill 设计，参与反馈治理与验收规则设计；协同实现本地 Demo，并参与验证与修订。

要解决的问题

跨天接手时，团队需要同时知道当前产物、已确认方向和下一责任人；新反馈还需要经过筛选与判断，才能影响后续选题。

02方案流程

让内容与决策依据一起交接。

DEMO / 工作台总览

候选、确认、版本与交接，在同一工作台中可见。

A运行对照
同一组反馈，对比直接使用、仅统计门槛与受控治理。
B人工确认
候选先停在人工环节，由内容负责人审阅并具名确认。
C结果与版本
候选已生成时，正式版本仍为 V1；确认后才更新。
D交接轨迹
逐步保留读取内容、交付物、下一责任人与停止条件。

03设计与实例

让下一位接手者知道怎么继续、何时停下。

业务背景｜持续生产与复盘的内容团队

工作场景
团队从素材整理推进到选题、大纲和成文，再根据发布反馈准备下一轮内容。工作会跨天、跨角色交接。
关键问题
有稿件不代表方向已确认；一篇内容互动较高，也不足以直接改变长期选题偏好。
设计目标
交接时保留产物、依据和下一责任人；调整方向时能追溯反馈来源、候选差异和确认人。

判断标准：接手者能否沿已确认方向继续工作，反馈是否具备分析资格，正式变更是否获得明确授权。

责任交接

把“已有何物”和“下一步由谁决定”一起记录。

我参与责任链与业务 Skill 设计，将各阶段输入、产物、状态和停止条件组织进交接约定。AI 生成阶段内容，人确认选题与大纲。

业务 Skill 承接的方法交付约定
选题准备将素材组织成候选，保留来源与判断依据，等待人工确认方向。
成文与审稿依据已确认方向组织内容与证据，交付稿件、审稿意见和继续条件。
指标整理与偏好更新记录发布反馈、检查分析资格，形成可审阅的偏好候选。

依据业务 Skill 与输入输出约定摘编；工作台 D 区展示对应的交接轨迹。

反馈治理与人工确认

合格反馈形成候选，正式变更由人确认。

我参与的设计
将反馈分析资格与正式变更权限分开：规则筛选反馈，AI 提出候选，负责人确认方向。
取舍理由
工具盘点短期互动高，不足以决定长期选题。保留一次人工审阅，结合反馈依据与长期方向做判断。
验证结果
固定 Demo 中，候选生成后仍为正式 V1；空姓名确认被拦截，具名确认后才更新为 V2。

固定教学模拟 · 反馈与偏好内容为示例，不调用模型

状态隔离

确认一篇文章，不应顺带改写长期偏好。

同一个 Demo 中，“确认当前文章理解”和“确认正式偏好变更”具有不同含义。我参与状态隔离规则与验收设计，让两条路径各自保存状态，避免确认动作影响另一条路径。

实时理解路径

文章输入 → 结构化理解 → 人工确认 → 等待外部发布与指标。

确认作用于当前文章；长期偏好保持原状。

固定对照路径

模拟反馈 → 偏好候选 → 具名确认 → 正式版本。

切换对照方式保留正式版本，明确复位才清除。

04交付与验证

把协作约定落成 Demo，再逐项核对行为。

  1. 01

    参与方案与规则设计

    梳理责任链、业务 Skill、反馈资格与人工确认边界，将输入输出及验收要求整理成实现依据。

  2. 02

    协同实现本地 Demo

    通过固定行为对照展示反馈治理，另设实时文章理解路径，明确各自的确认动作与状态范围。

  3. 03

    参与验证与修订

    用行为对照和自动化检查核对资格、权限与状态规则，参与问题修订和验收。

本地固定回归检查

检查动作已核对的行为
候选尚未确认／提交空姓名正式偏好保持 V1，空姓名确认被拦截。
具名确认候选形成正式 V2，并记录确认信息。
切换对照／明确复位切换保留 V2；明确复位后回到 V1。
确认实时文章理解进入等待外部发布与指标的状态，固定案例的偏好不变。

以上固定规则与状态检查已通过；实时路径的隔离检查使用测试输入，不依赖模型生成质量。

交付成果

产品方案、业务 Skill、反馈治理与验收规则，以及支持行为对照的本地 Demo。协作中的交接依据、人工确认和版本变化，都有对应的实现与检查。

项目完成到产品方案与 Demo 验证；外部发布和指标回收为人工环节。
