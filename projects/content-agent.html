PROJECT 02

内容协作 Agent

让 Agent 接续内容生产，把发布反馈转为负责人可审阅的方向建议。

01项目概览

内容团队要将素材推进为选题、大纲和文章，再根据发布反馈调整后续选题。一篇刚发布的文章即使互动较高，也不足以改变长期方向。

我的判断：把“反馈够不够分析”与“建议值不值得采用”分开。我参与 Agent 交接、业务 Skill 和反馈规则设计，协同实现 Demo 并参与验证与修订。

完成产品方案与 Demo 验证 · 下文为固定模拟案例

02Agent 如何接续工作

我参与定义交接时必须带上的产物与依据：下一位 Agent 不只拿到一段文字，还要知道来源、待补问题和当前稿件版本。

  1. 选题策划 → 内容主笔交接候选、来源与经负责人确认的大纲。
  2. 内容主笔 → 审稿编辑交接文章包；审稿输出修改清单与证据缺口，来源不足或版本不一致时停止。
  3. 人工发布 → 数据分析与复盘人工回收指标，Agent 分析合格反馈并提出后续选题建议。

03哪些建议值得采用

先筛选反馈，再判断是否改变方向

观察时长、样本与重复记录由规则检查；内容含义和方向建议由 Agent 分析。负责人再结合长期重点决定是否采用。这样，数据达到分析条件不会直接触发正式方向变更。

审阅一条建议：增加“上下文工程”主题的选题关注

固定样例中的建议与依据摘编
审阅什么样例给出的依据
哪些反馈被纳入上下文工程主题的历史文章进入合格样本；候选比较按固定样例达到差异门槛。
哪些反馈被排除一篇新发布的模型主题文章尚未达到观察时长，不纳入长期方向分析。
这个方向能交付什么内容关联选题可以将上下文整理方法转为产品经理可执行的做法。
还缺什么材料关联选题只有一份完整正文，发布前需要补充第二来源。

负责人据此审阅建议是否符合团队方向；关联文章的来源缺口也单独保留，不因建议进入审阅而视为内容已经可以发布。

体验：建议出现后，正式方向何时改变？

固定模拟 · 审阅并确认建议；输入仅保留在当前页面。

对照方式

受控路径：合格反馈形成候选，正式变更需具名确认。

正式偏好 V1

保持当前正式偏好；候选建议增加上下文工程主题的选题关注。

候选等待负责人确认

可切换对照方式；点击复位可重新体验。

04交付与验证

已形成产品方案、业务 Skill、Agent 交接与反馈规则，以及固定对照 Demo。验证覆盖了候选待审、负责人确认和正式版本更新；确认当前文章的大纲，只推进当前文章，不改写长期选题偏好。
