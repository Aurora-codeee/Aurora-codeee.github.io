PROJECT 03

AI 多人协同工作台

让成员与各自的 Agent 接续任务，分清工作草稿和已确认结论。

01项目概览

多人各自用 Agent 推进项目时，任务背景需要反复说明，写完的方案也可能还有待确认规则。我独立设计并搭建工作台，提供初始化、开工、接单、收工入口，以及查看进度的看板。

我的判断：个人工作过程与公共结论分开。Agent 可以整理材料和起草，但草稿必须经过本人确认与接收方验收，才能成为其他成员的正式依据。

独立设计与搭建 · 交接证据来自多角色仿真协作记录

02成员怎样使用

  1. 加入工作区搭建者配置成员和公共规则；新成员通过初始化 Skill 建立个人工作区与收发件入口。
  2. 带着任务开工或接单成员使用场景提示词，Agent 整理背景、相关成果与待决问题；本人确认输入清单后推进任务。
  3. 交回成果，更新进度成员确认交付与任务状态；看板向进度关注者呈现当前任务、关联记录和阻塞问题。

03一次具体交接

活动规则页写好了，但奖励规则还没有确认

在模拟的活动筹备任务中，页面方案编写者已经写好规则草稿，但中奖概率、奖励资源总量和每日投放量仍需资源负责人确认。此时把草稿直接交给下游，会让未确认的规则被当作定论。

同一次交接的记录摘编：从待确认草稿到共同依据
环节这次交接发生了什么
投递问题编写者附上草稿和依据，请资源负责人确认三项规则。
收到回复负责人说明：概率并非单独配置，需结合每日投放、剩余资源与当日参与规模理解。
本人确认编写者将回复写回对照表，确认后形成正式交付版本；回复不直接覆盖草稿。
交回验收业务发起人按任务要求检查已确认的对照表。
共享成果验收后的版本进入公共区，保留来源记录、整理人和日期，供后续引用。

我设计的是从提问到验收的交接规则，具体业务判断由对应角色给出。案例留下了草稿、回复和正式成果之间的对应关系，接手者可以查到规则由谁确认。

Agent 应读取哪些材料？先按任务选，再确认版本

我设计任务输入清单与分层索引：先读取共同背景，再按事项、相关人员和文件状态查找资料，由本人确认清单。个人区保存草稿与过程，公共区提供共同规则和已验收成果，避免把他人的过程材料当成当前结论。

理解和起草交给 Agent，投递与归档交给脚本

Agent 辅助拆解任务、整理依据和起草回复；脚本处理投递、归档与规则校验。任务状态提交后通过 Git Hook 同步到公共工作台，公共侧收到更新后生成看板与索引。

成员仍需确认输入、回复跨角色问题，并在收工时更新状态。遇到材料不足或无法承接的任务，可以退回说明补充条件；跨角色分歧保留人工裁决入口。

04已完成的搭建

已交付初始化 Skill、四类场景提示词、个人与公共工作区、可视化看板及投递归档和同步脚本。多角色仿真保留了一条完整交接记录：待确认的问题取得回复，经本人确认和发起人验收，形成可追溯的共享成果。
